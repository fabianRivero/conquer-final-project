The change creates the whole application: 17 file groups, 69 concrete files, 53 requirements across 8 capabilities, 3 test layers plus a Render/Neon deployment spine. No single PR can hold 400 changed lines. The owner chose **`feature-branch-chain`**: PR #1 targets the feature/tracker branch, each later PR targets the immediately previous PR branch so every review diff stays focused, and only the tracker merges to `main`. PR #1 base = the feature/tracker branch; PR #2 base = PR #1's branch; PR #3 base = PR #2's branch; and so on through PR #7. A child PR that would show a previous PR's changes has the wrong base and must be retargeted or rebased before review.
