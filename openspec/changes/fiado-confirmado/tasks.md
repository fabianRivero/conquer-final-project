The v2 model changes the change. The change creates the whole application: 15 file groups, 72 concrete files, 48 requirements across 8 capabilities (the `dispute-resolution` capability is gone), 3 test layers plus a Render/Neon deployment spine. No single PR can hold 400 changed lines. The owner chose **`feature-branch-chain`** in the v1 round and that choice still holds: PR #1 targets the feature/tracker branch, each later PR targets the immediately previous PR branch so every review diff stays focused, and only the tracker merges to `main`. A child PR that would show a previous PR's changes has the wrong base and must be retargeted or rebased before review.

**What the v2 model changed, and what it left alone.** The dispute machinery and the `nota de crédito` are gone. The client never writes to the ledger: it reads its own statement and *proposes* a payment. The charge exists only at the moment the client confirms, on the shop's screen, and the staff session records it. Three entities are born — `FiadoPropuesto`, `PropuestaLinea`, `PagoPropuesto` — and the entity count goes from twelve to fifteen. `LEDGER_ENTRY_KINDS` drops from three values to two. `Confirmacion` drops from two states to one. `LedgerEntry.cargo_id` is gone. The itemisation becomes **mandatory**: a charge without lines cannot exist. A customer never holds a credit: a `pago` never exceeds the debt it retires, and the excess leaves the counter as change (ADR-26). A payment's repartition is **recorded** as `ImputacionPago` rows, one per (payment, charge) pair, with the grain of the **charge** — so a client's charges read 8/8, 7/7 and 5/15 for a 20,00 € payment against charges of 8,00 €, 7,00 € and 15,00 € (ADR-27).

**What the v2 model does not touch.** Phases 1, 5, 6 and 7 of the v1 plan were never delivered, so they are re-planned here against the v2 contract rather than rewritten. The deployment spine (§18.1), the landmine list (§12.2) and the ADR set for the inherited design (§4, ADR-1…15) carry over unchanged.

## Notes

- **The v1 task list is superseded, not deleted.** The v1 plan had 71 tasks across 7 phases; this one has **69 across 7** - phases 2 to 8. The phase numbering follows the v1 numbering where the content survives (4, 5, 6, 7) and is renumbered where the content changed (2 and 3 are rewritten; the credential-boundary phase becomes 8).

- **Size budget deviation.** The skill's "under 530 words" target is arithmetically unreachable for this change: 15 file groups / 72 concrete files, 48 requirements across 8 capabilities, 9 credential RED tests plus 7 scope/leak tests, 3 test layers and a deployment spine. Following the precedent set by the design phase, the complete actionable content is kept and the deviation is stated here rather than dropping mandated content.
- **Test command form.** `pytest` is not on PATH — the form is `python -m pytest`. `black`, `ruff`, `vitest` and `playwright` are not installed.
- **Database.** The integration suite runs on **PostgreSQL 16**, never SQLite — landmine 7. The unit suite runs with no database by construction. The local environment is rebuilt by `scripts/setup-toolchain.ps1`.
- **Ordering.** Tests are written RED first: domain unit tests → model constraints and partial indexes → API contract → leak walk → concurrency → e2e (§15.4).
- **Conditional capability.** The facilitation is gated by **N5**, which on the current decision is **closed**: the four proposal routes answer 403 to the `dependiente` (task 5.6) and the capability is not built. If N5 opens, the `dependiente` gains exactly one proposal — the one it prepared — and tasks 5.5 and 5.6 are the only ones that change.
- **Regla cuts stay live.** If a validation round contradicts Regla 4, the client surface and the ten Regla-4 requirements are cut with it; if it contradicts Regla 5, `Producto` and `CargoLinea` leave the model and the `desglose` becomes a single amount; if it contradicts Regla 6, `StockMovement` and `existencias_registradas` leave with CP-07. No rule of the system changes (§19).
- **The `comprobante` is a planned extension, not implemented.** A `PagoPropuesto` carries an `importe` and a text `referencia`; no file, no upload, no attachment model (ADR-25).
- **Not touched.** `openspec/changes/tienda-barrio/` and `openspec/explorations/` are not modified; nothing is written under `openspec/specs/`.
